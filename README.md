# KC Treasury — RTDB login

## ตั้งค่าและอัปโหลด

1. สำรอง Realtime Database และ Rules ก่อนแก้ไข. เว็บนี้ใช้โปรเจกต์ `kc-smart-6e44d` และอ่านบัญชีผู้ดูแลจาก `system_config/admin_accounts/<key>/{username,password}` ที่มีอยู่แล้ว. ชื่อผู้ใช้คือค่าของ `username` ไม่ใช่ชื่อ `<key>`. ไม่ต้องสร้างบัญชีแอดมินใน Firebase Authentication
2. หน้าแอดมิน `/login`: กรอก username และ password ตามข้อมูล RTDB. ตัวเลือก “ล็อกอินค้างไว้” จะใช้ localStorage; หากไม่ติ๊กจะใช้ sessionStorage. หน้า `/treasury` จะจำสถานะบน browser เดิมจนออกจากระบบหรือล้างข้อมูล
3. หน้า Dashboard นักเรียน `/student-login` ใช้รหัสนักเรียน 5 หลักและจดจำด้วย localStorage; ต้องเปิด **Anonymous** ที่ Firebase Authentication → Sign-in method สำหรับโค้ดนักเรียนที่รวมในชุดนี้. หน้า `/dashboard` แสดงเฉพาะยอดและประวัติรายวันของรหัสที่กรอก ไม่แสดงค่าใช้จ่ายของห้อง
4. หาก Rules ปัจจุบันเป็นชุดเข้มงวดจาก ZIP รุ่นก่อน ให้นำ `database.rules.example.json` ไปใช้โดยตรวจสอบ path อื่นในฐานข้อมูลที่เว็บอื่นใช้ด้วย. ไฟล์นี้อนุญาตให้ browser อ่าน `admin_accounts` เพื่อเทียบรหัสผ่าน และอนุญาตให้อ่าน/เขียนข้อมูลคลังจาก browser; จึงไม่เหมาะกับข้อมูลส่วนตัวจริง. หาก Rules เดิมของคุณมี `.read: true` และ `.write: true` ที่ root เว็บจะเข้าถึงข้อมูลได้อยู่แล้ว และกฎ `.read: false` ด้านล่างปิดทับไม่ได้. ไม่ต้องเพิ่ม `admin_uids`
5. อัปโหลดไฟล์ HTML, CSS, JS และ `vercel.json` ไปที่ root ของโปรเจกต์ Vercel. เปิด `/` หรือ `/student-login` สำหรับนักเรียน; `/login` สำหรับแอดมิน. URL ไม่มี `.html`. ถ้าเปลี่ยนโดเมน เพิ่มโดเมนใน Firebase Authentication → Authorized domains

**ข้อจำกัดที่ต้องทราบ:** ระบบ login ฝั่งแอดมินวิธีนี้อ่านบัญชีและตรวจรหัสผ่านใน JavaScript บน browser. ผู้ที่เปิดเว็บสามารถอ่านรหัสผ่านจาก RTDB และแก้ session ใน browser ได้ หาก Rules เปิดให้เขียนข้อมูลคลัง คนอื่นก็แก้ยอดเงินโดยไม่ล็อกอินได้. การซ่อนหน้า `/treasury` เป็นเพียง UI ไม่ใช่การคุ้มครองข้อมูล. เพื่อปกป้องเงินจริงและข้อมูลนักเรียน ควรย้ายการพิสูจน์ตัวตนไป Firebase Auth หรือ server และตั้ง Rules บังคับสิทธิ์. รหัสนักเรียนอย่างเดียวก็ไม่ยืนยันว่าเป็นเจ้าของรหัสนั้น

หลังภาพที่มีรหัสแอดมินถูกเผยแพร่ ควรเปลี่ยนรหัสผ่านที่บันทึกใน RTDB ด้วย. รหัสผ่านไม่ถูกฝังไว้ในไฟล์เว็บไซต์

## หากหน้าเหรัญญิกแสดง 0.00 และ “กำลังคำนวณ…” ค้าง

รุ่นนี้เปลี่ยนสถานะด้านล่างจากข้อความคงที่เป็นผลโหลดจริง และแจ้ง error บนหน้าเว็บภายในประมาณ 12 วินาที. หากเห็น “โหลด script.js ไม่สำเร็จ” ให้ตรวจว่ามี `script.js` อยู่ข้าง `treasury.html` ใน deployment และ deploy ZIP ทั้งชุด. หากเห็น “ไม่มีสิทธิ์อ่านข้อมูล” ให้ตรวจ Rules ที่ `students` และ `system_config/daily_targets`. หากเห็น “ยังไม่มีการตั้งเป้าหมาย” แสดงว่าโหลดสำเร็จแต่ `daily_targets` ไม่มีรายการ. ไฟล์ favicon 404 เป็นแค่ไอคอนของแท็บ ไม่ทำให้ยอดเงินเป็นศูนย์ (รุ่นนี้ใส่ไอคอนไว้แล้ว)
